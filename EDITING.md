# Editing the profile

- **Text, project links, colors:** `profile/content.json`.
- **Network layer sizes and dimensions:** `profile/network.json`.
- **Neurons and connections:** `scripts/artwork.py`.
- **Panel spacing and responsive layout:** `scripts/render.py`.
- **Generated files:** `README.md` and `assets/profile*.svg`; do not edit by hand.

Run `python3 scripts/render.py` after editing. Python 3.10+; no packages or API
requests required. Run `python3 -m unittest discover -s tests` for verification.

The network is original abstract artwork, not a depiction of a project's actual
architecture. All adjacent layers are fully connected, with uniform red edges and outlined
neurons. Both themes share the same geometry.

Public repo and star counts are generated by `scripts/stats.py`. Run that before
`python3 scripts/render.py` to refresh them. The daily/manual GitHub Action uses
the built-in token, follows pagination, and commits only changed output. API
failures preserve the last good snapshot and images. Counts use owned public
non-fork repos and sum stars over exactly that set. Commit/line totals use the optional ACCESS_TOKEN history scan described below.
The Neural networks link still leads to the existing neural-network repository;
ii-gentoo links to the verified Gentoo overlay. StriZ remains plain text.

## Artwork alternatives

The generator also writes all three options to `assets/variants/`, in desktop and
mobile sizes for both themes. `network-*` retains the current neural network;
`compression-*` uses a signal landscape; `warp-*` uses a schematic GPU warp trace.
The new artwork functions live in `scripts/artwork.py`. These are illustrations,
not measurements. The main README uses the variant selected by `artwork` in `profile/content.json`
(currently `warp`).

The shared panel now uses code-block typography and dotted leaders. The warp option
uses the flowing vector trace: edit `warp_artwork()` in `scripts/artwork.py`. The embedded SVG is an image, not selectable README text.

Use `null` between row groups for one single-dot spacer line. A row such as
`{"section": "Previous"}` produces a heading with a horizontal text rule. Values use the theme `value`
color; labels use `accent`. Long values wrap automatically on narrow layouts.

The README image URLs include a deterministic content hash. Regenerating changed
SVGs changes the URLs, preventing stale GitHub image caches from hiding edits.

## All-time commit and line totals

`history.py` follows the approach in Andrew6rant's `today.py`, implemented separately:
it enumerates token-visible repositories where the account is an owner,
collaborator or organization member, then scans each default branch's complete
history. There is no date cutoff. The author must be mapped to the `jwihardi`
GitHub account. Commits shared between repositories/forks count once by SHA.
Additions/deletions are summed from those commits, including merges and generated
files; these are accumulated changes, not current source-code size. Side branches,
deleted/inaccessible histories and authorship not linked to the account are not
included. The snapshot can decrease after history rewriting or access loss.

Setup:
1. Create a fine-grained personal access token belonging to `jwihardi`, with
   **Contents: read** and **Metadata: read** for the repositories to include.
   A fine-grained token has one resource owner: selecting `jwihardi` covers that
   account's chosen private repositories plus public access, not other owners'
   private repositories. Organization policies/approval still apply. A broader
   authorized credential is needed to cover private repositories across owners.
2. Store it as `ACCESS_TOKEN` in this repository's Settings → Secrets and variables
   → Actions → New repository secret. Do not put it in a file or chat.
3. Run Actions → Refresh profile → Run workflow. It also runs daily at 08:17 UTC.

Without this secret, public repo/star counts still refresh; history totals are
omitted until a real successful scan. Existing totals keep their original date
if the token is later absent. An API failure with a configured token fails the
refresh before the public snapshot or SVGs change. Only totals and the observation
date are published. No private repository names, commit messages or file paths
are written into the profile.

The ignored `.cache/history.enc` cache is encrypted with a key derived from the
token before GitHub Actions caches it. It is never committed. A changed branch tip
invalidates that repository, including force-pushes with unchanged commit counts.
Removed repositories are dropped; token rotation triggers a fresh scan. Clear the
Actions cache for a full rescan after changing the account's linked author emails.

Local history scans/tests additionally need `cryptography>=44,<47` installed in a
virtual environment. Run `ACCESS_TOKEN=... python scripts/stats.py` using a securely
injected environment variable, then `python scripts/render.py`. Rendering and
public-only fetching still use the standard library. The workflow installs the
cache encryption dependency automatically.

Large-history fallback: if GraphQL repeatedly returns an internal error, the
scanner retries smaller pages, then tries the REST commit-history endpoint with
the same author and pinned head. If that also fails, it uses GitHub's indexed
commit search. Indexed results must be complete and below the 1,000-result cap;
each matching commit is checked for ancestry against the pinned head before its
line counts are added. Incomplete/capped results abort publication. Indexed
histories are rechecked on subsequent runs because search indexing can lag.
Encrypted per-repository checkpoints survive failures, but public totals and SVGs
are published only when the whole scan succeeds.

Two additional preview variants are generated: `fourier-*` (elliptical harmonic
epicycles and their trajectory) and `gpu-die-*` (an exploded abstract GPU package).
Their drawing functions are in `scripts/artwork.py`. They share all profile data
and palettes; neither changes the selected live artwork.
